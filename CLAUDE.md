# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Angular 22 SSR personal portfolio site, scaffolded from `angular-frontend-template` and implementing the 6-page Figma "Personal Portfolio Web Template" (Home, About, Services, Works, Blog, Contact), using Tailwind CSS v4 for styling and built-in Angular i18n (Spanish) for content. Package manager is **yarn** (not npm) — `yarn@1.22.22` is pinned via `packageManager`, and `angular.json` sets `cli.packageManager` to `yarn`. Node version is pinned in `.nvmrc` (24.16.0).

## Commands

- `yarn start` — run the dev server (`ng serve`) at `http://localhost:4200`.
- `yarn build` — production build (SSR output) to `dist/`.
- `yarn watch` — development-configuration build in watch mode.
- `yarn test` — run unit tests via the Angular CLI's Vitest-based unit-test builder (`@angular/build:unit-test`). To run a single test file, pass it through: `yarn test --project Angular-Frontend-Template -- src/app/path/to/file.spec.ts` (or invoke `vitest` directly against the file once tests exist).
- `yarn lint` — `ng lint`, backed by `@angular-eslint/builder` and the flat ESLint config in `eslint.config.js`.
- `node dist/Angular-Frontend-Template/server/server.mjs` — run the built SSR server (also exposed as `yarn serve:ssr:Angular-Frontend-Template`).
- `ng generate component <name>` (or other schematics) — scaffolding uses the `angular-eslint` schematic collection (configured in `angular.json`), and generated components default to `style: css`.
- `ng extract-i18n` — regenerates `src/app/shared/infra/i18n/messages.es.json` from `i18n="@@id"` markers in templates.

Lint-staged is configured in `package.json` (`eslint --fix` for `*.ts,html`; `prettier --write` for `*.ts,html,css,json,md`) and Husky is initialized (`.husky/`), but no hook script currently invokes lint-staged — it isn't automatically wired to `pre-commit` yet.

## Architecture

**Structure is context-first, not layer-first.** Feature code lives under `src/app/context/<context-name>/...` rather than in global `components/`/`pages/` folders. Within a context, code is further organized by layer, e.g. `context/home/ui/page/<page-name>/`. Each of the 6 site sections is its own context (`context/home`, `context/about`, `context/services`, `context/works`, `context/blog`, `context/contact`), each currently holding a single top-level page under `ui/page/<page-name>/`. Shared/cross-cutting code lives under `src/app/shared/`: `shared/infra/i18n/`, `shared/ui/` (base component kit — see Styling below), and `shared/layout/` (page-shell components rendered once around the router outlet, e.g. `Sidebar` — see `shared/layout/README.md`). There's also one dev-only context, `context/design-system`, gated behind `environment.isDesignSystemEnabled` in `app.routes.ts` (and shown as a "Componentes" entry in the sidebar under the same flag) — not one of the 6 real site pages. When adding a new page or feature, follow this pattern: create/extend a context directory and place the page under `ui/page/<page-name>/`, with the component file named `<page-name>.page.ts` and its template `<page-name>.page.html`.

Routing is lazy per-page: `app.routes.ts` uses `loadComponent: () => import('./context/.../<name>.page').then((m) => m.<ClassName>)` for each route rather than eagerly importing components.

**SSR setup**: this is an Angular SSR app (`@angular/ssr`), with separate config for browser and server:
- `app.config.ts` — browser `ApplicationConfig` (router, hydration, global error listeners).
- `app.config.server.ts` — merges `app.config.ts` with `provideServerRendering(withRoutes(serverRoutes))`.
- `app.routes.server.ts` — server rendering strategy per route (`RenderMode`); currently everything is `RenderMode.Prerender`. New routes that shouldn't be statically prerendered need an entry here.
- `server.ts` — the Express entry point (`AngularNodeAppEngine`), where API endpoints would be added if needed (none exist yet); exports `reqHandler` for platforms like Firebase Cloud Functions and self-starts on `PORT` (default 4000) otherwise.

**i18n**: uses Angular's built-in `i18n`/`i18n="@@id"` template attributes (not a runtime library like ngx-translate). Source locale is `"source"`; the only target locale is `es`, translated in `src/app/shared/infra/i18n/messages.es.json` (configured in `angular.json` under `projects.Angular-Frontend-Template.i18n`). `@angular/localize/init` is a polyfill, and `localize: ["es"]` is set on the build target. When writing template text meant to be user-facing, add an `i18n="@@<context>.<key>"` attribute and update the corresponding entry in `messages.es.json`.

**Styling**: Tailwind CSS v4, wired through PostCSS (`@tailwindcss/postcss` in `.postcssrc.json`) rather than a `tailwind.config.js`. The theme is defined via CSS custom properties in `src/styles.css` using Tailwind v4's `@theme` block; extend that block (not a JS config file) to add design tokens. Tokens are extracted from the Figma source file, not invented: `ink` (`#141313`, near-black — the only text/background neutral, used at full opacity or via Tailwind's `/opacity` modifier, e.g. `text-ink/60`, rather than a fabricated gray scale) and the brand gradient stops `brand-purple`/`brand-coral`/`brand-orange` (combine as `bg-linear-to-r from-brand-purple via-brand-coral to-brand-orange` for decorative panels — Tailwind v4's canonical gradient utility name; `bg-gradient-to-r` still works as a deprecated alias but new code should use `bg-linear-to-r`). Fonts: `font-sans` (IBM Plex Sans — body/headings/UI) and `font-serif` (IBM Plex Serif Bold — logo mark only), loaded via a Google Fonts `<link>` in `src/index.html`. The design has square corners everywhere (no border-radius) — don't add `rounded-*` unless a specific Figma frame shows it. Component styles default to plain CSS per `angular.json` schematics (`"style": "css"`); in practice, Tailwind utility classes in the template are enough and most components (all pages, all of `shared/ui/`) have no `styleUrl` at all — only add a `.css` file when Tailwind utilities genuinely can't express something.

**Base component kit** (`src/app/shared/ui/`, documented in `shared/ui/README.md`): `Button` (`app-button`, `variant: 'primary' | 'secondary'`), `Card` (`app-card`, structural wrapper), `TextField` (`app-text-field`, underlined label+input/textarea), `Icon` (`app-icon`, renders an SVG from `public/icons/` by `name`). These were extracted from Figma's `get_design_context`/`get_metadata`/`download_assets` output (via the `claude.ai Figma` MCP connector) and adapted to Angular signals (`input()`/`model()`) — reuse them instead of re-deriving styles from Figma when building out page content, and extend `IconName` in `icon.ts` (plus a new file in `public/icons/`) when a page needs an icon that isn't there yet.

**Environments**: `src/environments/environment.type.ts` defines the `Environment` interface; `environment.ts` / `environment.prod.ts` implement it. Production builds file-replace `environment.ts` with `environment.prod.ts` (configured in `angular.json`). Content that's real but likely to change independently of code — `socialLinks: { name: IconName; url: string }[]`, `contactPhone`, `contactEmail` (consumed by `Sidebar`/page heroes) — lives here rather than hardcoded in a component, and must be duplicated in both `environment.ts` and `environment.prod.ts` (there's no shared base between them). `isDesignSystemEnabled` (`true` only in `environment.ts`) is the single flag gating the dev-only design system route/nav entry — prefer adding a similar boolean flag over inline `NODE_ENV` checks when gating other dev-only behavior.

**Real photos/media**: an unprocessed copy of any real photo a user supplies goes in `assets/originals/` at the repo root (outside `public/`, so Angular's asset glob never ships it) — this is a deliberate backup, not dead weight, so don't delete it during cleanup. The actual served, cropped/optimized version goes in `public/images/`. When a supplied photo has a busy/distracting original background or colors (e.g. sponsor branding on clothing) but the subject is already isolated on a transparent background, keep the served asset as a PNG (not JPG — JPG has no alpha) and prefer stylizing it with CSS at render time over baking a treatment into the raster file: apply `grayscale` to the `<img>`, then layer a `mix-blend-color` div using the brand gradient (`bg-linear-to-br from-brand-orange via-brand-coral to-brand-purple`) clipped to a diagonal band with an arbitrary Tailwind clip-path utility over the torso only (keep the face/head untouched) — see `home.page.html`'s hero photo for the reference implementation. This both matches the Figma reference's grayscale-photo-with-a-colorful-diagonal-reveal treatment and neutralizes distracting original colors (e.g. sponsor-branded blue/yellow) without editing the source photo.

## Conventions

- Selectors: components use `app-` kebab-case element selectors, directives use `app` camelCase attribute selectors (enforced by ESLint rules in `eslint.config.js`).
- TypeScript is strict-leaning: `noImplicitOverride`, `noPropertyAccessFromIndexSignature`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, plus Angular's `strictInjectionParameters` and `strictInputAccessModifiers` are all enabled in `tsconfig.json`.
- Prettier: single quotes, 100-character print width, and the `angular` parser for `.html` files (`.prettierrc`).
- Component classes use standalone Angular API style (`imports: [...]` on `@Component`, no `standalone: true` needed since it's the default in this Angular version), and the signal-based `input()`/`model()` APIs for component inputs and two-way bindable state (see `shared/ui/`) rather than the `@Input()`/`@Output()` decorators.
- **Two i18n whitespace/projection gotchas that produce silent, hard-to-spot bugs:**
  - Angular strips a text node between two sibling elements if that text is *only* a newline/indentation — it does **not** collapse it to a single space like normal HTML. Two adjacent `i18n`-marked inline elements (e.g. `<span i18n="...">es</span>\n<span i18n="...">Santiago</span>`) render glued together with no space, even with a literal space between them on the same source line, once i18n substitution is involved. Fix: put both fragments inside **one** `i18n` block with the emphasized part as a plain nested element (`<span i18n="...">es <span class="font-bold">Santiago</span></span>`) rather than as two separately-translated siblings — the translation string then carries the placeholder as `{$START_TAG_SPAN}...{$CLOSE_TAG_SPAN}` (build once to see the exact placeholder name Angular expects, then match it in `messages.es.json`).
  - Never put more than one `<ng-content />` for the same slot across mutually-exclusive `@if`/`@else` branches in a component template (e.g. an "`<a>` vs `<button>`" toggle) — Angular fails to project into either branch. Factor the shared projected content into one `<ng-template #x>...<ng-content /></ng-template>` and render it via `<ng-container *ngTemplateOutlet="x" />` in each branch instead (see `shared/ui/button/button.html`).
